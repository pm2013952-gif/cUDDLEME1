Web hosting y dominios

Una página web es un conjunto de archivos. Para que otras personas la vean, esos archivos deben estar en un servidor conectado a internet (hosting), y alguien debe poder encontrarlos con un nombre fácil de recordar (dominio).

Web hosting

El hosting es el servicio que guarda tus archivos en un servidor que está encendido todo el tiempo y los entrega a quien los pida.

Tipo Cómo funciona Útil para
Compartido Varios sitios comparten un mismo servidor Sitios pequeños con poco tráfico y presupuesto bajo
VPS Una parte reservada de un servidor, con control sobre el sistema Proyectos que necesitan configuración propia
Nube Recursos repartidos en muchos servidores que crecen según la demanda Sitios con tráfico variable o que deben escalar

Cómo funciona Vercel para sitios estáticos

Un sitio estático son archivos HTML, CSS y JS que no necesitan procesarse en el servidor, como este. Vercel es una plataforma en la nube pensada para publicarlos:

  1. Conectas tu repositorio de GitHub a Vercel.
  2. Vercel toma los archivos y los publica en su red de servidores repartidos por el mundo (CDN), así la página carga desde un lugar cercano.
  3. Te da una URL pública con el formato nombre-proyecto.vercel.app y HTTPS incluido.
  4. Cada vez que haces git push, Vercel vuelve a desplegar el sitio automáticamente.

Dominios

Un nombre de dominio es la dirección legible de un sitio (como cuddleme.com). Reemplaza a la dirección IP, que es un número difícil de recordar. Se compra por año a un registrador.

tienda.cuddleme.com
  • TLD (dominio de nivel superior): el final del dominio, como .com (comercial), .net (redes) o .org (organizaciones).
  • Dominio: el nombre que eliges, junto a su TLD.
  • Subdominio: una sección antes del dominio, como tienda en tienda.cuddleme.com, que sirve para separar partes del sitio.

Propagación DNS

El DNS es la "guía telefónica" de internet: traduce dominios a direcciones IP. Así ocurre una consulta:

  1. Escribes tienda.cuddleme.com en el navegador.
  2. El navegador y el sistema operativo buscan la IP en su memoria (caché). Si no la tienen, preguntan al resolver DNS de tu proveedor de internet.
  3. El resolver consulta a un servidor raíz, que lo envía al servidor del TLD (.com).
  4. El servidor del TLD indica cuál es el servidor DNS autoritativo del dominio, que guarda los registros reales.
  5. El servidor autoritativo responde con la dirección IP del hosting.
  6. El navegador se conecta a esa IP y recibe la página. La respuesta queda en caché por un tiempo.

Cuando cambias un registro DNS (por ejemplo, apuntar tu dominio a Vercel), los servidores del mundo no se enteran al instante: cada uno guarda la respuesta anterior hasta que vence su TTL (tiempo de vida). A ese reparto gradual se le llama propagación y puede tardar desde minutos hasta 48 horas.
